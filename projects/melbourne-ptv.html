Melbourne Public Transport Patronage Analysis

This project analyses Melbourne public transport patronage using public datasets from Victoria. The project focuses on data integration, SQL/Python preparation, and analytical modelling to understand how transport demand changed across modes, locations, and time periods.

Business Problem

Public transport demand changes over time due to work patterns, population movement, service changes, and post-disruption recovery. Decision-makers need clear analysis of which modes and locations are recovering, which remain below historical demand, and how patronage varies across time.

Key Questions

  • How has public transport patronage changed over time?
  • Which transport modes show stronger or weaker recovery?
  • How do weekday and weekend travel patterns differ?
  • How can multiple public datasets be combined into a reliable analytical model?

Data & Tools

  • Dataset: Victorian public transport datasets
  • Tools: SQL, Python, Excel, data modelling
  • Techniques: public data integration, data cleaning, grain alignment, SQL modelling, exploratory analysis

Approach

  1. Collected and reviewed multiple public transport datasets.
  2. Identified the grain of each dataset before combining them.
  3. Cleaned and prepared data using Python and SQL.
  4. Designed a structured analytical model for mode, time, and location analysis.
  5. Created metrics to compare patronage recovery and travel pattern differences.

Key Insights

  • Different transport modes may recover at different rates after major demand changes.
  • Weekday and weekend patronage patterns can reveal different user behaviours.
  • Public datasets require careful grain checking before integration.
  • A structured SQL model improves the reliability of public-sector analytics.

Business Recommendations

  • Compare recovery by transport mode before making service-planning decisions.
  • Separate weekday and weekend analysis to avoid hiding different travel behaviours.
  • Use recovery index metrics to communicate patronage change clearly.
  • Maintain transparent data documentation because public datasets often have different structures and update frequencies.

Project Value

This project demonstrates my ability to work with messy public datasets, think carefully about data grain, integrate multiple sources, and build an analysis that can support public-sector or operational decision-making.
